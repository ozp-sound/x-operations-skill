# X 运营 Skill

用于发现选题、撰写 X 帖子、撰写 X Premium 长文，以及为后续发布准备内容。核心目标是：真实、像本人、少套话，不虚构经历和结果。

## 先判断交付类型

### 普通帖子

如果用户说“写一条帖子”“写几个帖子”或明确要求短内容：

- 默认写成可直接发布的短文本
- 不加标点符号，除非用户临时要求保留
- 不强行加标题、解释或长篇背景
- 保留口语、停顿感、个人判断和适度自嘲
- 不把用户写成成功人士、行业专家或已经实现收入目标的人
- 多条内容应有不同切入点，不要只替换几个词

### X 长文或文章

如果用户说“写长文”“写文章”“X 长文”或要求完整结构：

1. 先问：“这篇属于哪一种文章类型？”
2. 如果用户提供了五种类型的原文、截图或链接，先按其分类；若来源不可访问，不能自行编造五种类型，应请用户补充。
3. 用户选定类型后，按该类型的开头、展开、转折、结尾流程写。
4. 文章正常使用标点符号。
5. X Premium 长文可以使用标题和分段，但避免把每一段写成营销文案。
6. 涉及当前规则、价格、平台政策、金融、法律或健康内容时，先查可靠的最新来源；只写能确认的事实。

## 写作基调

- 第一人称优先，使用有限视角，不替用户补充没有说过的经历。
- 具体场景优先于抽象金句：宿舍、排练、网吧、地铁、家教、项目卡壳等细节可以保留。
- 允许矛盾和不确定性，不把焦虑改成励志演讲。
- 删除“赋能、重塑、拥抱、至关重要、开启新篇章”等宣传性 AI 词汇。
- 少用三段式排比、否定式金句、过多破折号和“总之、此外、然而”。
- 句子长短要有变化，段落不要机械等长。
- 使用人性化中文编辑原则：保留意思和事实，去掉填充、套话、虚假权威和过度总结。

## 常用内容方向

用户真实可写的方向包括：

- Codex、vibe coding、AI 工具和新手体验
- 大学生生活、财富观、家教、技能变现和项目试错
- 架子鼓、乐队、排练、演出和夜生活
- Human-first 社交产品：少广告、少操纵式推荐、AI 辅助但不代替人表达
- 对互联网成功学、AI 创业焦虑、实习秋招话语的个人观察

写项目内容时只能使用已确认的信息。可以写“正在做”“还在测试”“目前的想法”，不能写成已经上线、已经盈利、已经获得用户，除非用户明确提供证据。

## 运营流程

### 选题

先确认用户要：热点评论、个人经历、项目进度、工具分享、观点表达，还是纯幽默内容。当前热点和平台规则必须实时核对，不能凭旧记忆写“最新”。

### 成稿

普通帖子直接给成稿。长文先确认文章类型，再按类型成稿。用户说“humanize”或任务明显需要自然表达时，应用本项目的 `humanizer-zh` 技能。

### 审核

发帖前检查：事实是否来自用户或可靠来源，是否有夸大收入、虚构结果、未经授权的个人信息、金融确定性承诺或可能误导读者的表述。

### 发布边界

默认只起草，不自动发布。登录、验证码、付费、账号设置和最终发布都需要用户明确确认。可以协助浏览趋势、准备文案和整理配图，但不要把“已写好”说成“已发布”。

## 配图

用户要求封面或配图时使用 `imagegen`。先确定横版或竖版、是否需要留标题空间、是否有人物、画面风格和禁止元素。生成后将最终文件复制到项目 `assets/`，并返回可点击的绝对路径。

## 输出习惯

- 帖子：使用 `social_post` 写作块，正文不加标点。
- 长文：使用 `social_post` 写作块，保留标题、分段和正常标点。
- 多个版本只在语气确实不同或用户要求时提供，最多三个。
- 解释修改时简短直接，不要把写作建议写成另一篇文章。
